# Film graphics, imagery and captions

Product scenes are filmed as built; do not recolor their accurate product UI.
Frames and graphics use the same approved brand snapshot as the prototype, via `brand.js` and `brand.css`.
See [brand frames](brand-frame.md).

`graphics.html` gets story data from `film.json` through `gfx_data.py`; don't edit shared templates per film.
Night/morning graphics are optional story transitions, not a required narrative order. A simulation needs actual
illustrative engine output; never fabricate a measured result. Use the configured endcard or prototype closing,
not both.

- Use configured typography, approved logo variants and palette, with actual readable contrast.
- Keep titles conversational and brief; marked key phrases use the configured accent.
- Concept/fictitious-data labels stay visible. Key content stays above the caption zone (roughly bottom 190px).
- No borrowed Tredence wordmark, hashtag, palette or photography in generic output.
- If no imagery was approved during onboarding, use the approved flat background and report it.
  Ask for additional scene-specific images only when the requested story needs assets not already supplied.
- Never generate images unless explicitly requested. Respect permissions and use fictional people.
- Verify all stills before recording; check logos, font loading, clipping and caption clearance.

Captions use the selected brand font and configured colors, keeping written numbers even when speech uses
expanded pronunciation. Check contrast over both product and frame footage. Keep captions on by default,
with readable chunks and enough time to read; never hide the concept footer.

The close states the business change, illustrative value and a specific ask if appropriate.
An optional sign-off uses saved brand text, not a forced hashtag.
